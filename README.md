# dsh-style-fingerprint

Плагин DeepSeek Harness: русский текст, который понимает человек вне контекста.

Человек читает только текст: задачи, файлов и вчерашнего разговора у него нет, поэтому
ответ без объяснений он понять не может. Плагин превращает это требование в механизм:
перед письмом модель получает закон, шаблон жанра и чек-лист, после письма — проверку,
которая называет место, нарушенное правило и правку. В сессии модель видит инструмент
`style` с семью действиями, раздел системного промпта и скилл `style`.

## Как это работает

1. Перед документом модель вызывает `style` с действием `brief` и называет жанр и
   читателя. Ответ содержит профиль проверки, шаблон жанра со слотами, чек-лист, целевые
   интервалы метрик и три цитаты из корпуса.
2. Модель пишет по шаблону.
3. Перед отправкой модель вызывает `style` с действием `check`. Ответ перечисляет
   нарушения с местами в тексте и правками, метрики против целей, вердикт `pass`, `warn`
   или `fail` и оценку от 0 до 100. Нарушения с пометкой `error` модель исправляет до
   отправки.

Проверка судит по одному профилю: профиль называют именем или словом жанра, а вызов без
имени берёт профиль по умолчанию, сейчас `chat_answer`. Слои работают иначе: слой с галкой
добавляет свои правила к любому тексту. Страница настроек живёт в Settings → Plugins →
«Стилевой отпечаток» и держит два блока — «Профиль по умолчанию» с выбором одного профиля
и «Разрешённые профили» с галками; профиль без галки вызов не примет.

## Установка

Нужны DeepSeek Harness с профилем (проверено на профиле `desktop`), Node.js 20 или новее
для тестов и Python 3.11 или новее для движка метрик. Репозиторий склонируйте в постоянный
каталог и поставьте движок:

```powershell
git clone https://github.com/LeoLourson/StyleFingerprint-DSH.git dsh-style-fingerprint
cd dsh-style-fingerprint
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`pymorphy3`, `natasha` и `torch` занимают около 1 ГБ. Они идут в `.venv` плагина, а не в
системный Python. Дальше подключите каталог плагина к профилю ссылкой и запишите пакет в
файл профиля:

```powershell
$plugin  = "C:\путь\к\dsh-style-fingerprint"
$profile = "$env:USERPROFILE\.dsh\profiles\desktop"
New-Item -ItemType Junction -Path "$profile\node_modules\dsh-style-fingerprint" -Target $plugin
```

В `$profile\package.json` пакету нужны две записи — зависимость и бандл профиля:

```json
{
  "dependencies": {"dsh-style-fingerprint": "file:C:\\путь\\к\\dsh-style-fingerprint"},
  "dsh": {"profile": {"bundles": ["dsh-style-fingerprint"]}}
}
```

Перезапустите приложение: бандлы профиля оно читает при старте, а карточка в Settings
приходит вместе со страницей, поэтому после установки перезагрузите и страницу. Проверить
плагин без перезапуска приложения можно тестами:

```powershell
node --test "tests/*.test.mjs"
.venv\Scripts\python.exe -m pytest tests/test_metrics.py -q
```

## Быстрый старт

Вызов из сессии называет жанр и читателя, ответ приходит в сокращённом виде:

```json
{"action": "brief", "genre": "readme", "audience": "владелец DSH, который решает, ставить ли плагин", "length": "около 120 строк"}
```

```json
{
  "profile": "technical_doc",
  "template": {"path": "templates/readme.md", "slots": ["имя проекта", "одно предложение", "…"]},
  "checklist": ["Первый абзац говорит, что это и зачем (R-LAW-02)", "…"],
  "targets": {"metrics": {"syntax.sent.len.mean": {"min": 12, "max": 32}}},
  "samples": [{"id": "tolstoy/anna-karenina#1", "text": "Все смешалось в доме Облонских. …"}]
}
```

Проверка готового текста судит по одному профилю и называет места нарушений:

```json
{"action": "check", "profile": "chat_answer", "text": "Таким образом, в этом разделе мы разберём очень важный вопрос."}
```

На испорченном тексте из трёх таких фраз проверка 13.11.2026 дала `verdict: "fail"`,
`score: 92` и три нарушения: `lang.connective.empty` (R-LANG-04, три вхождения),
`lang.amplifier.unmeasured` (R-LANG-01) и `lang.metatext.announce` (R-LANG-02). У каждого
нарушения есть место в тексте и правка.

## Профили

| профиль | для чего | слои | шаблоны |
|---|---|---|---|
| `chat_answer` | ответ в диалоге | central, language | `answer.md` |
| `technical_doc` | отчёт, README, план | central, composition, language, classification | `report.md`, `readme.md`, `plan.md` |
| `business_letter` | письмо, сообщение | central, language | `letter.md` |
| `prose_essay` | эссе, объяснение | central, composition, language, author, corpus | `essay.md` |
| `math_paper` | математическая статья | central, composition, language, math | `math-article.md` |

Художественной прозы среди профилей нет: роман живёт по другим интервалам, чем рабочий
текст. Образцы прозы служат в корпусе цитатами и опорой правил.

## Слои и правила

Каждый слой — файл `law/` одного формата: паспорт, правила `R-<слой>-<номер>` со
свойством, действием и проверкой, примеры до и после, чек-лист. Номер `R-*` из `law/`
связывает правило с машиночитаемой записью в `data/rules.json`, поэтому число, место и
правка в отчёте проверки указывают на одно и то же правило.

| слой | файл | что задаёт |
|---|---|---|
| central | `law/00-central.md` | закон «текст для человека вне контекста», читается всегда |
| language | `law/10-write-for-outsider.md`, `law/30-language.md` | адресат, первый абзац, основание, канцелярит, связки |
| composition | `law/20-composition.md` | тезис, линия доказательства, границы, финал |
| author | `law/40-author-voice.md` | чужой голос: что берут из прозы, а что нет |
| corpus | `law/45-russian-prose.md` | образцы русской прозы как цитаты и опора правил |
| classification | `law/50-classification.md` | одно основание на уровень, списки, имена |
| math | `law/55-math-article.md` | математическая статья: теорема, доказательство, обозначения |

## Отпечаток

Стилевой отпечаток — 120 метрик в 11 группах: синтаксис, морфология, глубина дерева,
номинализации, дискурс, нарратив, лексика, пунктуация, абзац, стиль и маркеры ИИ-текста.
У метрики есть единица (`per1000` — на 1000 слов, `share` — доля от единицы, `ratio`,
`mean`, `count`, `entropy`) и спецификация в `reference/metrics.md`.

Проверка судит не все метрики, а ворота: от 8 до 14 на профиль, остальные отдаёт действие
`measure` справочно. Целевые интервалы лежат в `data/targets.json`, у каждого есть
источник: `rule` — из правила, `corpus` — из образцов, `author` — из выбранного автора.

Метрики считает один движок на Python (`tools/analyze.py`, pymorphy3 и natasha). Плагин
держит его дочерним процессом: один запуск, дальше ответ приходит за десятые доли
секунды. Второй реализации на JavaScript нет, поэтому числа проверки и числа движка
совпадают. Без Python проверка идёт по правилам из `data/rules.json`, а метрики получают
пометку `unavailable` с причиной.

## Корпус

| корпус | произведений | слов | цитат |
|---|---|---|---|
| Толстой | 7 | 134 340 | 269 |
| Достоевский | 7 | 132 879 | 265 |
| Шкаликов, математические статьи | 74 | 323 665 | 647 |

Текстов в репозитории нет: лежат манифест и цитатный индекс, поэтому поиск цитат и
проверка работают сразу после клонирования. Тот, кому нужны сами тексты, собирает их
четырьмя командами:

```powershell
.venv\Scripts\python.exe tools/fetch_corpus.py
.venv\Scripts\python.exe tools/build_index.py
.venv\Scripts\python.exe tools/fetch_math_corpus.py
.venv\Scripts\python.exe tools/build_math_index.py
```

Тексты пришли из Викитеки и lib.ru, статьи — с Math-Net.Ru со страницы автора. В манифесте
у каждого произведения есть заголовок, жанр или журнал, год, источник, `sha256`, число слов
и знаков. Что не вошло, там же стоит с причиной: старая орфография, дубль версии, некролог,
юбилейное поздравление, английский текст без русского оригинала, скан без текстового
слоя, закрытый полный текст. Цитаты — отрывки прозы в 25–120 слов; индексы цитат скрипты
собирают из текстов, поэтому цитату можно проверить против её файла.

Математический корпус лежит отдельно, в `corpus/math`, и литературный каталог не
дополняет. Текст статей приходит из текстового слоя PDF: переносы склеивает сборка,
колонтитулы она снимает, абзацы восстанавливает эвристикой. Формулы в таком слое искажены,
поэтому в цитаты идут абзацы без формул. Слов вне словаря pymorphy3 в статьях 6,1 %, в
литературе 2,0 % (слова из трёх и более кириллических букв, 14 литературных произведений и
74 статьи, 13.11.2026).

## Устройство

```
law/          закон и слои: правила R-*, примеры, чек-листы
templates/    семь шаблонов жанров: answer, report, readme, plan, essay, letter, math-article
reference/    справочники: паттерны, связки, маркеры ИИ-текста, спецификация метрик
data/         rules.json, metrics.json, targets.json, profiles.json, settings.json
corpus/       литература: manifest.json, text/, index.json
corpus/math/  статьи Шкаликова: manifest.json, shkalikov/, index.json
tools/        сборка корпусов и движок метрик analyze.py
requirements.txt  версии pymorphy3, natasha и torch для движка
index.js      хост-половина: инструмент style, раздел промпта, скилл, мост к Python
client.js     клиентская половина: страница Settings → Plugins
tests/        node: инструмент, раскладка, клиент; pytest: метрики
```

`CONTRACT.md` задаёт форматы файлов и API инструмента, `PLAN.md` — что построено и чем
проверено, `DEFERRED.md` — что решено не строить.

## Ограничения

- Плагин описан только для русского текста: закон работает с русской морфологией и
  синтаксисом, английский профиль не заведён.
- Корпус мал для распределений: 134 тыс. слов Толстого и 133 тыс. слов Достоевского дают
  цитаты и опору правил, но не норму. Поэтому числа по образцам не служат эталоном, а у
  целевых интервалов чаще источник `rule`.
- Художественная проза не проверяется: у неё другие интервалы, профиля для неё нет.
- Без Python плагин проверяет только правила по регулярным выражениям; метрики и ворота
  по ним недоступны.
- Автоматической перепроверки ответа на конце хода и жёсткой блокировки отправки нет: в
  DSH нет хука, который мог бы остановить отправку. Порядок держится на разделе промпта и
  на том, что модель вызывает `check` сама.
- Примеры команд даны для PowerShell на Windows. На Linux и macOS меняются пути профиля,
  путь к интерпретатору (`.venv/bin/python`) и команда `ln -s` вместо junction.

## Проверено

13.11.2026 на Windows 11, профиль `desktop`: инструмент `style` отвечает из сессии, раздел
стиля пришёл в системный промпт, `check` на тексте с нарушениями назвал их места, `brief`
по жанру `readme` вернул шаблон `templates/readme.md`, набор node — 39 тестов (38 прошли,
один пропущен), pytest — 16 тестов. Карточку в Settings → Plugins в живом приложении не
проверяли: клиентская половина приходит вместе со страницей.
