# План: dsh-style-fingerprint

Плагин DSH, который заставляет модель писать русский текст для человека вне контекста:
закон и порядок работы перед каждым документом и каждым ответом, шаблоны по жанрам,
измеренный отпечаток русской прозы (Толстой, Достоевский) с числами и порогами,
проверка готового текста с местами и правками, настройка профилей в Settings → Plugins.

## 1. Задача и критерий

Задача — адекватный русский текст: логика изложения, связность, грамматика, читаемость
человеком, который не видел нашей работы. Отпечаток служит воротами качества, а не
самоцелью: числа проверяют правила, правила объясняют числа.

Критерий готовности системы:

- модель перед написанием документа получает шаблон жанра и чек-лист, а не общие слова;
- перед выдачей ответа проходит проверку, которая называет место и правку;
- в корпусе Толстого и Достоевского измерены все заявленные метрики, у каждой есть
  разброс по произведениям и целевой интервал для повествовательного профиля;
- чистый текст не портится: проверка на корпусных фрагментах даёт `pass`;
- настройки: профили и слои включаются и выключаются в Settings → Plugins, значения
  доходят до инструмента без перезапуска;
- установка в профиль `desktop` через junction, инструмент виден в списке, раздел в
  системном промпте присутствует.

## 2. Критика исходной карты отпечатка

Карта из ответа пользователя (лексика, синтаксис, структура, пунктуация, идиосинкразия,
стабильность) в основном верна, но часть пунктов к корпусу XIX века неприменима или
измеряется иначе. Решения:

| Уровень карты | Решение | Причина |
|---|---|---|
| `bag of words` | выбросить | частоты содержательных слов измеряют тему, а не стиль |
| служебные слова | взять | неосознанный выбор, ядро стилометрии; метрика `w.service.*` |
| `type-token ratio` сырой | выбросить | зависит от длины текста; заменяем `w.mattr100` и `w.hapax.share` |
| идиомы и клише | взять как цитаты | в отпечаток идут образцами, а не числами |
| длина и разброс предложений | взять | `s.len.mean/median/p90/cv`, доли коротких и длинных |
| части речи | взять | нужна морфология: pymorphy3; без неё метрики POS не считаются |
| актив/пассив | упростить | пассив считается по `-ся` и кратким причастиям, точного разбора нет |
| порядок слов | выбросить | надёжного автоматического определения без парсера нет |
| маркеры дискурса | взять с типизацией | частота по отношениям (причина, следствие, уступка…) и разнообразие |
| длина абзаца, списки | взять | `p.words.mean`, `p.sentences.mean`, `p.one_sentence.share` |
| нарративные паттерны | упростить | доля диалога, длина реплики, глаголы речи; «сцена/обобщение» — правило, не метрика |
| пунктуация | взять | частоты на 1000 слов, отношение тире/двоеточие |
| эмодзи, капитализация, подпись | выбросить | в корпусе нет базы; остаются правилами чата (A6, C3) |
| хезитации, усилители | взять | списки, частота на 1000 слов |
| стоп-лист ИИ | взять | справочник де-ай; в хорошей прозе почти ноль, любое вхождение — дефект |
| «что автор никогда не делает» | взять | отдельный список запретов: безличные констатации, списки в сцене, заголовки внутри абзаца |
| внутриличностная вариативность | взять | разброс по произведениям и десятилетиям, пороги от p5–p95, не от среднего |
| один общий отпечаток | отвергнуть | поздний Толстой и Достоевский несовместимы: профили раздельные, общие черты — в правилах |

Добавлено сверх карты: доля абстрактных существительных и номинализаций, плотность
глаголов и отношение глагол/существительное, доля предложений с деятелем-подлежащим,
длина клауз, доля диалога, плотность глаголов речи, доля оценочных прилагательных.

## 3. Устройство

```
law/            закон и слои; 00-central читается всегда
reference/      справочники: паттерны, связки, наблюдения над корпусом
templates/      шаблоны жанров: ответ, отчёт, письмо, статья, README, коммит, план, сцена
data/           rules.json (паттерны, лексиконы), fingerprint.json (числа), profiles.json
corpus/         manifest.json + text/<author>/<work>.txt (тексты вне git)
tools/          fetch_corpus.py, metrics.py, build_fingerprint.py
index.js        хост: инструмент `style`, раздел промпта, runtime-скиллы
client.js       клиент: страница settings.plugins.tab с профилями и слоями
tests/          node: инструмент, раскладка, проверки; pytest: метрики
```

Порядок слоёв при конфликте: `00-central` → закон жанра (`10`–`50`) → отпечаток
(`45`) → справочник → шаблон. Слой ниже не отменяет закон выше.

## 4. Фазы и приёмка

**Ф1. Скелет и контракт (Lead).** Каталог, `.gitignore`, `PLAN.md`, `CONTRACT.md`,
`data/profiles.json`, `law/00-central.md`. Приёмка: `git status` чист, контракт
описывает все форматы и API.

**Ф2. Корпус (corpus-metrics).** Скачать с Викитеки произведения Толстого и
Достоевского, вычистить разметку и служебные блоки, собрать `corpus/manifest.json`.
Приёмка: не меньше 40 произведений и 1,5 млн слов на автора; нет старой орфографии
(`/ДО`), нет дублей версий; у каждого произведения автор, жанр, год, источник, sha256;
выборочная проверка трёх произведений совпадает с источником по началу и концу.

**Ф3. Метрики и отпечаток (corpus-metrics).** `tools/metrics.py` по спецификации
`reference/metrics.md`, `tools/build_fingerprint.py` → `data/fingerprint.json`.
Приёмка: 45+ метрик, у каждой p5/p50/p95 по авторам и жанрам; контрольный текст
получает те же числа в Python и в JS (допуск 1e-6); отпечаток воспроизводится
повторным запуском побайтно.

**Ф4. Законы, справочники, шаблоны (rulebook).** Пять скиллов сведены в `law/` и
`reference/` без потери правил и без дублей; `templates/` — девять шаблонов;
`data/rules.json` — машиночитаемые паттерны с идентификаторами и ссылками на источник.
Приёмка: каждое правило исходных скиллов имеет место в новой системе (таблица
соответствия в `reference/migration.md`); `rules.json` проходит схему; шаблон каждого
жанра содержит скелет, порядок, целевой объём и чек-лист.

**Ф5. Плагин (plugin).** Инструмент `style` (действия `brief`, `guide`, `check`,
`measure`, `corpus`, `fingerprint`, `config`), раздел системного промпта, runtime-скиллы,
клиентская страница настроек. Приёмка: фейковый контекст грузит модуль; инструмент
отвечает на всех действиях; `check` на испорченном тексте даёт нарушения с местами, на
чистом — `pass`; настройки из страницы меняют поведение без перезапуска.

**Ф6. Сборка, установка, демо (Lead).** Junction в `~/.dsh/plugins`, запись в профиле
`desktop`, перезапуск, проверка `dump-config`, демо до/после на трёх текстах, запись
в память проекта.

## 5. Стоп-условия

- Корпус не даёт 1,5 млн слов на автора за два часа работы — берём то, что есть,
  фиксируем в `corpus/manifest.json` поле `coverage` и продолжаем: отпечаток строится
  на достижимом объёме.
- Морфология недоступна (pymorphy3 не ставится) — POS-метрики помечаются `null`,
  отпечаток строится на остальных, в отчёте называется пробел.
- Страница настроек не получает хост-канал — настройки читаются из
  `data/settings.json`, страница показывает их и пишет файл через доступный канал;
  если канала нет вовсе, настройки правятся файлом, это фиксируется в README.
- Инструмент не регистрируется после перезапуска — проверяем `dump-config`, ищем
  двойной `id`, неверный `exports`, отсутствие записи в `dsh.profile.bundles`.

## 6. Риски

- Ложные срабатывания проверки на техническом тексте: пороги от прозы к технике не
  переносятся, поэтому у профилей разные целевые интервалы, а проверка сообщает
  профиль, по которому судила.
- Стилизация: имитация Толстого в отчёте читается как пародия. Отпечаток даёт
  свойства (конкретность, причинность, сцена), не манеру.
- Объём: 475 КБ исходных правил. Слои грузятся по запросу, в промпт идёт только
  `00-central` и чек-лист жанра.
- Расхождение Python и JS в метриках: закрывается контрольным текстом и тестом.
