# План: dsh-style-fingerprint

Плагин DSH, который заставляет модель писать русский текст для человека вне контекста:
закон и порядок работы перед каждым документом и ответом, шаблоны по жанрам, измеримый
стилевой отпечаток (набор метрик с целевыми интервалами), проверка готового текста с
местами и правками, настройка профилей в Settings → Plugins. Образцы русской прозы
Толстого и Достоевского лежат рядом и служат цитатами, а не источником порогов.

## 1. Задача и критерий

Задача — адекватный русский текст: логика, связность, грамматика, читаемость человеком,
который не видел нашей работы. Отпечаток — ворота качества: числа проверяют правила,
правила объясняют числа.

Критерий готовности:

- модель перед написанием документа получает шаблон жанра и чек-лист, а не общие слова;
- перед выдачей ответа проходит проверку, которая называет место, правило и правку;
- отпечаток — не меньше 100 метрик, посчитанных на тексте пользователя, с целевыми
  интервалами для пяти профилей; интервал помечен источником (`rule` или `corpus`);
- чистый текст не портится: проверка на эталонном фрагменте даёт `pass`;
- образцы: не меньше 120 тыс. слов у Толстого и у Достоевского, каждое произведение с
  автором, жанром, годом, источником, sha256; поиск цитат по образцам работает;
- настройки: пять профилей, шесть слоёв, строгий режим, запас порогов, пороги по
  метрикам, выбор автора, статус корпуса, проверка текста на странице — меняют
  поведение без перезапуска;
- установка в профиль `desktop` через junction, инструмент виден, раздел промпта на
  месте, страница в Settings → Plugins открывается.

## 2. Критика исходной карты отпечатка

Карта из ответа пользователя верна в основном, но часть пунктов к русской прозе XIX
века неприменима или измеряется иначе. Решения (пользователь принял критику и потребовал
её расширить):

| Пункт карты | Решение | Причина |
|---|---|---|
| `bag of words` | выбросить | частоты содержательных слов измеряют тему, а не стиль |
| служебные слова | взять | неосознанный выбор, ядро стилометрии |
| сырой `type-token ratio` | выбросить | зависит от длины; вместо него MATTR, hapax, Yule K |
| идиомы и клише | взять как цитаты | в отпечаток идут образцами, а не числами |
| длина и разброс фраз | взять | среднее, медиана, p90, коэффициент вариации, доли коротких и длинных |
| части речи | взять | морфология pymorphy3 |
| актив и пассив | упростить | пассив по `-ся` и кратким причастиям; точного разбора не обещаем |
| порядок слов | взять через парсер | инверсия и позиция подлежащего по дереву natasha |
| маркеры дискурса | взять с типом | частота по отношениям и разнообразие связок |
| длина абзаца, списки | взять | средняя длина, доля абзаца в одно предложение |
| нарративные паттерны | упростить | доля диалога, длина реплики, глаголы речи, доля сцен |
| пунктуация | взять | частоты на 1000 слов, отрезок между знаками, отношение тире/двоеточие |
| эмодзи, капитализация, подпись | выбросить | в корпусе нет базы; остаются правилами чата |
| хезитации, усилители | взять | списки, частота на 1000 слов |
| стоп-лист ИИ | взять | любое вхождение в прозе — дефект |
| «что автор никогда не делает» | взять | отдельный список запретов |
| внутриличностная вариативность | упростить | корпус мал для p5–p95; числа по образцам не выдаются за норму |
| один общий отпечаток | отвергнуть | поздний Толстой и Достоевский несовместимы: образцы раздельные |

Расширение сверх карты (обязательное требование): глубина и тип подчинения, обособленные
обороты, вид и наклонение глагола, доля абстрактных существительных и номинализаций,
длина клаузы, диалог и глаголы речи, повторы в окне, ритм и автокорреляция длин фраз,
анафорические цепочки, доля предложений с деятелем-подлежащим, инверсии по дереву,
плотность оценки и модальности, вставные конструкции, маркеры мета-текста.

## 3. Устройство

```
law/        закон (00) и слои 10-50 в едином формате: паспорт, правила R-xx,
            примеры до/после, чек-лист
reference/  справочники: паттерны, связки, наблюдения, спецификация метрик
templates/  семь шаблонов: ответ, отчёт, README, план, статья, письмо, статья-математика
data/       rules.json, metrics.json, targets.json, profiles.json, settings.json
corpus/     литература: manifest.json, text/<author>/<work>.txt, index.json (цитаты);
            математика: corpus/math/manifest.json, corpus/math/shkalikov/<mathnet>.txt,
            corpus/math/index.json
tools/      fetch_corpus.py, build_index.py, fetch_math_corpus.py,
            build_math_index.py, analyze.py (движок метрик), metrics_spec.py
index.js    хост: инструмент `style`, раздел промпта, входной скилл, мост к Python
client.js   клиент: страница settings.plugins.tab
tests/      node: инструмент, раскладка, паритет; pytest: метрики
```

Метрики считает один движок на Python (pymorphy3 + natasha). Инструмент держит его
дочерним процессом с обменом JSON-строками: один запуск, дальше ответ за десятые доли
секунды. Второй реализации на JS нет — паритет по построению. Python недоступен —
проверка работает по регулярным правилам, метрики помечаются `unavailable` с причиной.

Слои в едином формате:

```
---
id: law/language
title: Язык
order: 30
reads: on-demand
source: text-hygiene, paper-de-ai
rules: [R-LANG-01, ...]
---
## Что решает слой
## Правила
### R-LANG-01. Короткое имя
Свойство: ...
Действие: ...
Проверка: ...
## Примеры до и после
## Чек-лист
```

Идентификаторы правил: `R-<СЛОЙ>-<номер>` (LAW, LANG, COMP, AUTH, CLASS, MATH, CORP).
Машиночитаемое правило в `data/rules.json` ссылается на тот же идентификатор.

## 4. Что строим и чего не строим

Строим: пять профилей (`chat_answer`, `technical_doc`, `business_letter`,
`prose_essay`, `math_paper`); семь шаблонов; шесть слоёв (`central`, `language`,
`composition`, `author`, `classification`, `corpus`); корпус-образцы; движок метрик;
инструмент; страницу настроек; входной скилл; математический корпус статей
Шкаликова отдельным каталогом `corpus/math`.

Не строим и записываем в `DEFERRED.md`: пьесы, публицистика, письма и дневники в
корпусе; шаблоны коммита и сцены; автоматическую перепроверку ответа плагином;
жёсткую блокировку отправки; переключатель разборщика; парсер в настройках.

## 5. Работы и приёмка

**Р1. Документы (Lead).** `PLAN.md`, `CONTRACT.md`, `law/00-central.md`, профили,
настройки, `DEFERRED.md`, README. Приёмка: контракт описывает все форматы, API, мост,
границы работы; ни одного файла вне списка «строим».

**Р2. Образцы (corpus-scout).** Толстой: «Анна Каренина» (главы), «Хаджи-Мурат»,
пять рассказов. Достоевский: «Идиот» (главы), «Преступление и наказание» (главы),
пять рассказов. Викитека, на отсутствующее — lib.ru, источник в манифесте. Приёмка:
не меньше 120 тыс. слов на автора; нет старой орфографии и дублей версий; у каждого
произведения автор, жанр, год, источник, sha256; цитатный индекс собирается;
выборочная сверка трёх произведений с источником.

**Р3. Метрики (metricist).** `tools/analyze.py` (pymorphy3 + natasha), спецификация
`reference/metrics.md`, каталог `data/metrics.json` (100+), целевые интервалы
`data/targets.json`, `tests/test_metrics.py`. Приёмка: все метрики каталога считаются
на любом русском тексте; нет `null` без причины; контрольный текст даёт устойчивые
числа при повторном запуске; эталонный чистый фрагмент укладывается в цели профиля
`prose_essay`; испорченный текст выходит за цели.

**Р4. Законы и шаблоны (canon-writer).** `law/10`–`law/50` в едином формате,
`templates/` — семь шаблонов. Приёмка: каждое правило исходных пяти скиллов имеет
место (таблица в `reference/migration.md`); правила нумерованы и проверяемы; шаблон
содержит скелет, порядок, целевой объём, чек-лист и ссылки на правила.

**Р5. Паттерны (pattern-writer).** `reference/*` (кроме `metrics.md`), `data/rules.json`
со ссылками на `R-*`, списки ИИ-маркеров и запретов. Приёмка: каждое правило `rules.json`
ссылается на существующий `R-*`; регулярные выражения проходят проверку на компиляцию
и на ложные срабатывания в образцах (не больше 1 % абзацев на правило); `forbidden`
не срабатывает на цитатах и коде.

**Р6. Плагин (plugin-smith).** `index.js`, `client.js`, `package.json`, патч, локаль,
иконка, тесты. Приёмка: фейковый контекст грузит модуль; все действия `style`
отвечают; `check` на испорченном тексте даёт нарушения слоёв с местами, на чистом —
`pass`; мост к Python работает и переживает падение движка; страница настроек
соответствует правилам DSH UI и меняет поведение без перезапуска.

**Р7. Сборка и установка (Lead).** Junction в `node_modules` профиля `desktop`, запись
в `package.json` профиля (зависимость и список бандлов), пробный запуск профиля на
временном доме, перезапуск приложения, `dump-config`, демонстрация до/после, запись
в память проекта. Приёмка: плагин активируется без ошибки, инструмент виден, раздел
промпта на месте, карточка в Settings → Plugins открывается, маршрут страницы
отвечает.

**Р8. Математический корпус (Lead).** `tools/fetch_math_corpus.py`,
`tools/build_math_index.py`, `corpus/math/manifest.json`, `corpus/math/index.json`.
Приёмка: у каждого произведения заголовок, журнал, год, страницы, ссылка, sha256;
`words` и `chars` манифеста совпадают с файлом; каждое исключение названо причиной;
в репозитории нет PDF; индекс цитат не содержит формульных знаков.

## 6. Стоп-условия

- Образцы не дают 120 тыс. слов на автора за два часа — берём достижимое, пишем
  `coverage` и продолжаем.
- natasha не ставится или падает на Windows — синтаксические метрики помечаются
  `unavailable` с причиной, остальные работают; профиль проверки судит по доступным.
- Ложные срабатывания правила больше 5 % абзацев образцов — правило переводится в
  `warning` или снимается, причина в `reference/migration.md`.
- Страница настроек не получает канал к хосту — настройки читаются из `data/settings.json`,
  страница правит файл доступным каналом; если канала нет, правка файла и запись в README.
- Плагин не загружается после перезапуска — проверка `dump-config`, двойной `id`,
  `exports`, запись в `dsh.profile.bundles`.

## 7. Риски

- Стилизация: имитация Толстого в отчёте читается как пародия. Образцы дают свойства
  (конкретность, причинность, сцена), не манеру.
- Ложные срабатывания на техническом тексте: у профилей разные цели, проверка всегда
  называет профиль, по которому судила.
- Вес установки: pymorphy3 и natasha с torch — около 1 ГБ. Ставится в `.venv` репозитория,
  не в системный Python.
- Объём правил: 475 КБ исходных скиллов. В промпт идёт только `00-central` и чек-лист,
  остальное — по запросу.
