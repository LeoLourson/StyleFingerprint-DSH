# Контракт: форматы, API и границы

Плагин читает и пишет файлы в шести каталогах, отдаёт один инструмент и держит один
дочерний процесс на Python. Файл фиксирует форматы этих файлов и ответов, чтобы правка
одного места не разошлась с другим. Читают его до первой правки: тот, кто меняет формат,
и тот, кто пишет по формату — новый слой, новую метрику, новый сборщик корпуса. Форматы
проверяют `tests/layout.test.mjs` и `tests/tool.test.mjs`: формат, разошедшийся с этим
файлом, роняет тест.

Пути даны от корня плагина — каталога, в который склонирован репозиторий.

## Тексты корпуса

`corpus/text/<автор>/<произведение>.txt` — литература, `corpus/math/shkalikov/<mathnet>.txt`
— статьи. Оба каталога собираются скриптами и в git не попадают: в репозитории лежат
манифесты и цитатные индексы. Поэтому поиск цитат и проверка работают сразу после
клонирования. Сборка — `tools/fetch_corpus.py` и `tools/fetch_math_corpus.py`, индексы —
`tools/build_index.py` и `tools/build_math_index.py`.

Формат текста один для обоих корпусов: UTF-8 без BOM, перевод строки `\n`, один абзац на
строку, пустая строка между абзацами. Без заголовков глав, предисловий, комментариев,
примечаний, ссылок и служебных блоков источника. Фрагмент романа — целая глава; главы
разделены пустой строкой и строкой `## <роман>, часть <N>, глава <M>`.

Литература: Толстой — «Анна Каренина» (главы), «Хаджи-Мурат», «Крейцерова соната»,
«Смерть Ивана Ильича», «Кавказский пленник», «Севастополь в декабре месяце», «После
бала»; Достоевский — «Идиот» (главы), «Преступление и наказание» (главы), «Честный вор»,
«Белые ночи», «Кроткая», «Сон смешного человека», «Мальчик у Христа на ёлке». Целевой
объём — 130 тыс. слов на автора.

## Манифест литературы

`corpus/manifest.json` описывает состав и происхождение каждого произведения:

```json
{
  "version": 1,
  "built": "2026-11-12T23:59:24Z",
  "use": "exemplar",
  "coverage": {"tolstoy": {"words": 134340, "works": 7, "target": 130000},
               "dostoevsky": {"words": 132879, "works": 7, "target": 130000}},
  "works": [
    {"id": "tolstoy/anna-karenina", "author": "tolstoy", "title": "Анна Каренина",
     "genre": "novel", "year": 1877, "source": "wikisource", "url": "https://…",
     "file": "corpus/text/tolstoy/anna-karenina.txt", "chars": 242013, "words": 40098,
     "sha256": "…", "license": "CC BY-SA 4.0", "excerpt": "", "notes": ""}
  ],
  "excluded": [{"title": "…", "reason": "старая орфография"}]
}
```

Поля работы: `id` вида «автор/произведение», `author` ∈ `tolstoy`, `dostoevsky`, `title`,
`genre` ∈ `novel`, `novella`, `story`, `year` первой публикации или написания (`null`,
когда год неизвестен), `source` ∈ `wikisource`, `libru`, `url` страницы-источника,
`file` путь к тексту, `chars` и `words` файла, `sha256` его содержимого, `license`
лицензии источника, `excerpt` пометка о цитате, `notes` замечания сборки.

`words` — число разделённых пробелами отрезков текста, `chars` — длина файла в знаках; оба
числа считаются по файлу, и `tests/layout.test.mjs` сверяет их с файлом, когда тексты
собраны. `coverage` даёт сумму слов по автору и число произведений против целевого объёма.

Что не вошло, перечислено в `excluded` с причиной: старая орфография, дубль версии,
английский текст без русского оригинала, скан без текстового слоя, полный текст закрыт
сайтом.

## Цитатный индекс литературы

`corpus/index.json` хранит отрывки, которые плагин показывает как образцы:

```json
{"version": 1, "built": "2026-11-12T23:59:24Z",
 "excerpts": [{"id": "tolstoy/anna-karenina#12", "author": "tolstoy",
               "work": "Анна Каренина", "title": "Анна Каренина", "genre": "novel",
               "year": 1877, "kind": "paragraph", "text": "…", "words": 54}]}
```

Абзац в цитату идёт длиной от 25 до 120 слов, одна цитата приходится примерно на 500 слов
произведения, `kind` ∈ `paragraph`, `dialogue`, `scene`. Индекс собирает
`tools/build_index.py` из собранных текстов. Поэтому каждая цитата проверяема против
своего файла.

## Математические образцы

Второй корпус обслуживает профиль `math_paper` и живёт отдельно от литературного:
`corpus/math/shkalikov/<id>.txt` и `corpus/math/manifest.json`. Литературный каталог он
не дополняет и его манифест не меняет.

Автор — Андрей Андреевич Шкаликов, источник — Math-Net.Ru, страница персоналии
`personid=12042`. Текст берётся из текстового слоя PDF статьи, поэтому формулы в нём
искажены: они допустимы как шум и не годятся для цитат. Заголовок статьи, авторы,
аннотация, ключевые слова и библиография остаются: по ним видно, как устроено введение.

Состав — научные статьи, где Шкаликов автор, за все годы. Не входят некрологи, юбилейные
поздравления, заметки о человеке, коллективные тексты, где он не первый автор, статьи без
открытого полного текста, сканы без текстового слоя и английские переводы при наличии
русского оригинала: перевод не его язык. Каждое исключение записано в `excluded` с
причиной.

```json
{"version": 1, "built": "2026-11-13T01:01:12Z", "author": "shkalikov", "use": "exemplar",
 "coverage": {"shkalikov": {"words": 323665, "works": 74, "target": 150000}},
 "source": {"site": "mathnet", "person": 12042,
            "url": "https://www.mathnet.ru/php/person.phtml?personid=12042"},
 "works": [{"id": "shkalikov/mzm14738", "mathnet": "mzm14738", "title": "…",
            "journal": "Матем. заметки", "year": 2025, "pages": "299–319",
            "url": "https://www.mathnet.ru/php/getFT.phtml?jrnid=mzm&paperid=14738&what=fullt&option_lang=rus",
            "file": "corpus/math/shkalikov/mzm14738.txt", "chars": 0, "words": 0,
            "sha256": "…", "notes": ""}],
 "excluded": [{"mathnet": "rm607", "title": "…", "reason": "некролог"}]}
```

PDF после извлечения текста не хранится: в манифесте остаются адрес и `sha256` текста.
Повторный запуск сборки обязан дать те же файлы; статья, скачать которую не удалось,
попадает в `excluded` с причиной «нет открытого полного текста», а не в `works` с нулём
слов.

`corpus/math/index.json` — тот же цитатный индекс, но отрывки берутся только из прозы
статьи: абзацы введения, где нет формул и разметки. Абзац с символами формул в цитату не
идёт.

## Метрики

Спецификация лежит в `reference/metrics.md`: идентификатор, название, единица, формула
словами, минимальный пример, нужен ли разборщик. Единицы: `per1000` (на 1000 слов),
`share` (доля от единицы), `ratio`, `mean`, `count`, `words`, `entropy`.

Каталог `data/metrics.json`:

```json
{"version": 1,
 "metrics": [
   {"id": "syntax.sent.len.mean", "label": "Средняя длина предложения", "unit": "words",
    "needs": "none", "group": "syntax", "spec": "1.1"}
 ],
 "groups": {"syntax": "Длина и ритм", "morphology": "Части речи", "…": "…"}}
```

`needs` ∈ `none`, `morphology`, `syntax` — какая часть разбора нужна метрике. В каталоге
120 метрик в 11 группах; пороги, которые проверяет `tests/layout.test.mjs`: `syntax` 14,
`morphology` 12, `morphology.depth` 8, `nominal` 4, `discourse` 10, `narrative` 8, `lexis`
6, `punctuation` 10, `paragraph` 4, `style` 14, `ai` 10.

Целевые интервалы `data/targets.json`:

```json
{"version": 1, "marginDefault": 0.15, "updated": "2026-11-13",
 "profiles": {
   "chat_answer": {
     "syntax.sent.len.mean": {"min": 8, "max": 22, "source": "rule"},
     "ai.marker.per1000": {"min": 0, "max": 10, "source": "rule"}
   },
   "technical_doc": {}, "business_letter": {}, "prose_essay": {}, "math_paper": {}
 }}
```

`source` ∈ `rule`, `corpus`, `author` — откуда взят интервал: из правила, из образцов или
из выбранного автора образцов. Проверяются не все метрики, а ворота: от 8 до 14 на
профиль, остальные отдаёт действие `measure` справочно. Правило `kind: "metric"`
ссылается на метрику по идентификатору.

`margin` расширяет интервал на долю с каждой стороны и действует только вне строгого
режима: при `margin: 0.15` цель 8–22 проверяется как 6,8–25,3. Строгий режим снимает
допуск и делает промах метрики ошибкой, а не предупреждением.

## Правила

`data/rules.json` — единственный список проверяемых правил:

```json
{"version": 1, "built": "2026-11-13",
 "rules": [
   {"id": "lang.connective.empty", "ref": "R-LANG-14", "layer": "language",
    "title": "Пустая связка", "severity": "error",
    "profiles": ["chat_answer", "technical_doc", "business_letter", "prose_essay"],
    "kind": "regex", "pattern": "таким образом|в данной связи|в этой связи",
    "units": "per1000", "max": 2,
    "message": "Связка обещает вывод, которого нет",
    "fix": "Назвать отношение словом или снять связку",
    "source": "text-hygiene B4"},
   {"id": "lang.ai.metatext", "ref": "R-LANG-31", "layer": "language",
    "title": "Мета-текст", "severity": "error", "profiles": ["*"],
    "kind": "forbidden", "pattern": "в этом разделе|как уже было сказано",
    "message": "Текст говорит о себе, а не о предмете",
    "fix": "Убрать анонс или заменить содержанием",
    "source": "text-hygiene A9"}
 ],
 "stopwords": ["…"],
 "lexicon": {"connectives": {"cause": ["потому что", "так как", "поскольку"],
                             "consequence": ["поэтому", "так что", "отсюда"],
                             "contrast": ["но", "однако", "зато"],
                             "concession": ["хотя", "несмотря на", "пусть"],
                             "condition": ["если", "когда"],
                             "spec": ["то есть", "а именно", "причём"],
                             "addition": ["и", "к тому же", "вдобавок"]},
             "intensifiers": ["очень", "крайне", "весьма"],
             "hedges": ["возможно", "вероятно", "по-видимому"],
             "speechVerbs": ["сказал", "спросил", "ответил"],
             "abstractSuffixes": ["ость", "ание", "ение", "ция", "изм", "ство"]}}
```

`kind` ∈ `regex` (норма на `units`), `forbidden` (любое вхождение), `metric` (ссылка на
метрику и цель профиля), `manual` (только сообщение, проверки нет). `ref` — номер правила
в `law/`, обязательный для каждого правила: по нему нарушение в отчёте находит своё
правило в тексте закона. Регулярные выражения — синтаксис JavaScript без inline-флагов,
регистр игнорируется всегда. Идентификатор правила `rules.json` — `слой.тема.случай`,
латиницей.

Список правил один: вид правила называет `kind`, а не отдельный массив. Второго списка
запретов нет, иначе одно правило давало бы два отчёта об одном нарушении. `kind:
"manual"` в отчёт о нарушениях не попадает: он напоминает, что правило нужно прочитать.

### Частотная норма в коротком тексте

`units: "per1000"` задаёт плотность: `max` — сколько вхождений допустимо на 1000 слов.
Допустимое число вхождений в тексте считается как `max(1, max·слова/1000)`, то есть первое
вхождение не запрещено ни при какой длине. Без этого правила короткий ответ превращал бы
одно слово в ошибку: при `max: 1` норма требует 1000 слов, и в ответе на 40 слов одно
«очень» давало бы 25 вхождений на 1000 слов — нарушение из ничего. Выше одного вхождения
норма работает как обычно: два «очень» на сто слов дают 20 на 1000 при норме 2.

`units: "count"` — абсолютное число вхождений в тексте, от нуля. Так задают норму, у
которой само появление — нарушение, независимо от длины.

## Слои

Слой — файл `law/` одного формата: паспорт, правила `R-<СЛОЙ>-<номер>`, примеры до и
после, чек-лист.

```
---
id: law/language
title: Язык
order: 30
reads: on-demand
source: text-hygiene, paper-de-ai
rules: [R-LANG-01]
---
## Что решает слой
## Правила
### R-LANG-01. Имя
Свойство: что плохо для читателя.
Действие: что делать.
Проверка: как убедиться, что сделано.
## Примеры до и после
## Чек-лист
```

Слои: `law/10-write-for-outsider.md` (слой `language`, центральные формулировки),
`law/20-composition.md` (`composition`), `law/30-language.md` (`language`),
`law/40-author-voice.md` (`author`), `law/45-russian-prose.md` (`corpus`),
`law/50-classification.md` (`classification`), `law/55-math-article.md` (`math`).
`law/00-central.md` читается всегда и пишется в том же формате с `reads: always`.

Файл слоя — единственный владелец своего диапазона номеров; номер внутри диапазона не
переиспользуется после снятия правила. Ссылка `ref` в `data/rules.json` указывает на
существующий номер.

| Файл | Слой | Номера |
|---|---|---|
| `law/00-central.md` | `law` | без номеров, проверки называются словами |
| `law/10-write-for-outsider.md` | `language` | `R-LAW-01…19` |
| `law/20-composition.md` | `composition` | `R-COMP-01…19` |
| `law/30-language.md` | `language` | `R-LANG-01…39` |
| `law/40-author-voice.md` | `author` | `R-AUTH-01…09` |
| `law/45-russian-prose.md` | `corpus` | `R-CORP-01…09` |
| `law/50-classification.md` | `classification` | `R-CLASS-01…09` |
| `law/55-math-article.md` | `math` | `R-MATH-01…19` |

`profiles: ["*"]` означает «все профили» и допускается только у правил без нормы по
профилю: `kind: "forbidden"` и `kind: "manual"`. У `regex` и `metric` профили перечислены
явно: норма `max` у профилей разная, и «*» скрыл бы эту разницу.

## Шаблоны

`templates/` держит семь шаблонов: `answer.md`, `report.md`, `readme.md`, `plan.md`,
`essay.md`, `letter.md`, `math-article.md`. У каждого паспорт (`id`, `profile`,
`audience`, `length`), скелет со слотами, порядок работы, чек-лист и ссылки на правила.
Действие `brief` берёт шаблон по названному жанру; профиль говорит, какие шаблоны ему
доступны.

## Движок метрик и мост

`tools/analyze.py` — единственная реализация метрик (pymorphy3 и natasha). Два режима:
`python tools/analyze.py --serve` читает JSON-строки со стандартного ввода и отвечает
строкой на запрос, `python tools/analyze.py --stdin` обрабатывает один запрос и выходит.

Запрос: `{"id":"1","action":"measure","text":"…","options":{"language":"ru"}}`. Ответ:
`{"id":"1","ok":true,"result":{"metrics":{…},"counts":{"words":0,"sentences":0,"paragraphs":0},"unavailable":{}}}`;
при ошибке — `{"id":"1","ok":false,"error":"текст ошибки"}`. Действия: `ping`, `catalogue`,
`measure`. Первая строка при `--serve`: `{"ready":true,"metrics":0,"version":"0.1"}`.

Плагин держит процесс живым: запускает при первом `check` или `measure`, ждёт ответ не
дольше 20 с, перезапускает после падения не больше двух раз и завершает при выгрузке
плагина. Python недоступен — проверка идёт по `data/rules.json`, а ответ содержит
`"engine": {"available": false, "reason": "…"}`.

Путь к интерпретатору задаёт настройка `pythonPath`; по умолчанию плагин берёт
`<корень плагина>/.venv/Scripts/python.exe`, затем `python` из `PATH`.

## Инструмент `style`

| действие | вход | выход |
|---|---|---|
| `brief` | `genre`, `audience?`, `length?`, `language?` | `{profile, law: [{id,title,text}], template: {id,title,body,slots}, targets, checklist, samples}` |
| `guide` | `name` (`law/00-central`, `reference/…`, `templates/…`, короткое имя) | `{name, text}` |
| `check` | `text`, `profile?`, `strict?` | результат проверки |
| `measure` | `text` | `{metrics, counts, catalogue, engine}` |
| `corpus` | `query`, `author?`, `genre?`, `k?` | `{matches: [{id, author, work, genre, year, kind, text}]}` |
| `fingerprint` | `profile?`, `metric?` | `{profiles: {…}, targets, catalogue}` |
| `config` | — | действующие настройки и их источник |

`check` отвечает так:

```json
{"profile": "chat_answer", "verdict": "pass|warn|fail", "score": 92,
 "counts": {"words": 0, "sentences": 0, "paragraphs": 0},
 "metrics": {"…": 0}, "targets": {"…": {"min": 0, "max": 0}},
 "engine": {"available": true, "version": "0.1"},
 "violations": [{"rule": "lang.connective.empty", "ref": "R-LANG-14", "severity": "error",
                 "title": "…", "count": 0, "places": ["до 200 символов вокруг места"],
                 "message": "…", "fix": "…"}],
 "next": ["что сделать до отправки"]}
```

`verdict`: `fail` — есть ошибка; `warn` — есть предупреждение или метрика вне цели;
`pass` — нет ни того, ни другого. `score` — от 0 до 100, доля пройденных ворот и правил.
`notes` перечисляет то, что проверка не смогла судить: текст короче порога, метрика без
знаменателя.

## Настройки

`data/settings.json` хранит значения по умолчанию; страница Settings правит этот файл:

```json
{"version": 2, "enabled": true, "strict": true, "defaultProfile": "chat_answer",
 "profiles": {"chat_answer": true, "technical_doc": true, "business_letter": true,
              "prose_essay": true, "math_paper": true},
 "layers": {"central": true, "language": true, "composition": true, "author": true,
            "classification": true, "corpus": true, "math": true},
 "margin": 0.15, "author": "both", "pythonPath": "",
 "metricTargets": {},
 "gate": {"minWordsForCheck": 60},
 "changedAt": "2026-11-13T02:50:00+03:00", "changedBy": "…"}
```

`profiles` — разрешение, а не набор: каждое значение говорит, примет ли плагин вызов с
этим профилем, и судит проверка всегда по одному профилю. `defaultProfile` называет
профиль для вызова без имени. `layers` складывается: включённый слой добавляет правила к
любому тексту. `author` ∈ `tolstoy`, `dostoevsky`, `both` — чьи образцы цитируются.
`gate.minWordsForCheck` — порог, ниже которого проверка считает метрики, но не закрывает
ворота по ним.

Действующие настройки — `settings.json`, недостающие поля берутся из `data/profiles.json`.
Плагин читает файл по времени изменения: правка со страницы или руками действует без
перезапуска.

## Проверки

`node --test "tests/*.test.mjs"` прогоняет четыре набора: `tool.test.mjs` грузит модуль
фейковым контекстом Cordis, проверяет все действия инструмента, нарушения с местами,
настройки без перезапуска и шаблон по жанру; `layout.test.mjs` сверяет пути контракта,
схемы данных, номер `R-*` у каждого правила, совпадение манифеста с собранными текстами и
правила страницы; `engine.test.mjs` поднимает мост к Python, роняет движок и смотрит, что
плагин пережил падение; `client.test.mjs` загружает клиентскую половину и ловит чтение
службы без `inject`.

`.venv\Scripts\python.exe -m pytest tests/test_metrics.py -q` считает все метрики каталога
на контрольном тексте и сверяет значения из `tests/fixtures/metrics-sample.json` с
допуском 1e-6; повторный запуск даёт те же числа.

Установку проверяет пробный профиль на временном доме: копия профиля и бандла в `%TEMP%`,
затем `dsh --profile probe --no-open --port 0`.
